# 改进方案与比较设计

本文件使用抽象或合成场景说明常见工作方法，不包含具体参赛论文、结果或优胜方案。

## 从不足选择改动

| 不足的证据 | 可研究的改动 | 需要特别检查 |
|---|---|---|
| 简化机理在特定条件下出现系统偏差 | 恢复有依据的机制或使用分区模型 | 新参数是否可标定；收益是否只是额外自由度造成 |
| 目标只反映平均表现，失效情景不可接受 | 加入与任务相符的风险度量或可靠性条件 | 风险定义、概率估计误差和情景依据 |
| 前问误差显著影响后问决策 | 传播估计不确定性，比较稳健决策 | 信息时序、联合不确定性及保守程度 |
| 判据过粗，漏掉边界事件 | 改进判据或自适应细化关键区域 | 漏检测试、复杂度，以及精度收益能否传到最终输出 |
| 计算成本来自重复或冗余状态 | 利用结构降维、缓存或分解 | 等价条件、近似误差和同精度运行成本 |
| 结果依赖人为固定但非题目要求的选择 | 将其作为变量，或比较合理备选 | 是否仍满足原题；新增自由度是否带来不可辨识 |

这些是候选机制，不是自动有效的“创新标签”。发现明显错误时先建立正确基线，再讨论额外改进。

## 最小比较说明

在运行前写清当前要检验的主张和观察到什么将否定它。

| 内容 | 需要确定的问题 |
|---|---|
| 基线 | 是否实现了相同题意、数据和约束；是否经过必要校验 |
| 改进 | 哪一个可定位模块变化，其他部分是否保持可比 |
| 评价 | 误差、可行性、成本或风险如何计算；单位和统计口径是什么 |
| 精度与预算 | 比相同精度的成本，还是固定预算下的质量；如何报告不对等条件 |
| 不确定性 | 结果中的抽样波动、参数不确定性和离散误差分别如何估计 |
| 失败 | 哪些场景下不改善、违反约束或超过预算；何时回到基线 |

## 合成例一：两个模块的收益不能混算

设基础方案为 $B$，候选在其中增加参数调整模块 $A$ 与局部网格细化模块 $G$。若主张是两者都有效，可比较 $B$、$B+A$、$B+G$ 与 $B+A+G$，并核对相同输出精度下的时间成本。

若 $B+A$ 未改善而完整方案改善，不能据此宣称 $A$ 有独立贡献；它也可能只与 $G$ 存在交互作用。若任务预算不足以区分贡献，应缩小主张而不是填补未做的消融结果。

## 合成例二：约束变化与方法变化分开

假设基线在容量 $C$ 下给出方案，候选同时改变求解方法并把容量改为 $C+\Delta$。目标改善可能来自容量增加。验证方法贡献，应在同一容量下比较；扩容情景可以保留，但作为单独的决策分析。

## 报告已有证据

结果记录应能说明主张依据于哪个模型版本、数据、参数和运行。留存失败或不改善的情景，有助于表达适用范围。没有外部数据时，合成验证可检查实现或参数回收，但不能代替真实场景有效性证据。
