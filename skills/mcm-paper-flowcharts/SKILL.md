# 论文流程图

把实际输入、模型、计算和验证关系画清楚。先确定拓扑，再设置样式；已有参考图只提供获准使用的内容和视觉依据，不把其题目、参数或结果带入新问题。

## 确定模式和交付

- 忠实复现：保持原图文字、结构、条件、比例和配色；不要借美化纠正模型或删节点。重建位图不能声称逐像素一致。
- 逻辑整理/美化：按当前模型简化重复表述、调整方向和分组，保留数学含义。章节先后不自动变成因果箭头。
- 未指定格式时以可编辑 `.drawio` 为主文件。用户指定PPTX时，使用环境中实际可用的原生形状/文本/连接符工具；无法提供该格式时说明限制，不能把XML改扩展名或整图贴入PPT冒称全元素可编辑。
- 不依赖任何专有插件或打包运行时。PPTX以及PNG/PDF导出属于环境可用时的选项，不擅自安装软件或变更用户交付要求。

## 建立图的逻辑

从目标范围的来源中建立简短节点表（ID、角色、标签、输入/输出、来源位置）与边表（起终点、关系、条件）。明确数据流、推导、并行汇合、判断和反馈，不强制每问都有训练、优化或定理。

判断出口标注真实条件；缺少分支行为时先指出，不为对称补造步骤。反馈指向实际更新的变量或步骤。总图保留跨问交接物，细节放分图；并行关系不能因排版变串行。未开展的检验不得画成已完成结果。

## 可编辑实现

使用 [布局输入与实现](references/implementation.md) 中的标准库脚本：
```text
python scripts/render_drawio.py INPUT.json OUTPUT.drawio
```

脚本生成未压缩draw.io XML：节点是原生框体与文字，边是连接符，可改标签和位置。输入JSON采用显式坐标，不自动解决复杂布局或字体测量；它会检查重复ID、未知端点、非法坐标和出界节点。新建布局从 `assets/example-flow.json` 的通用合成流程开始，不覆盖技能示例。样式规则见 [视觉与逻辑检查](references/visual-checks.md)。

需要PPTX时根据已确认的节点/边表用可用办公库重建原生对象，保留对象层次与连接语义；不将私有运行时列为依赖。公式保持可编辑文本或原生公式；复杂公式如必须作为图像嵌入，明确哪些元素不可编辑。

## 验收与交付

1. 检查每个节点/边与来源对应，条件、变量名、并行与反馈未改变含义。
2. 在可用的diagrams.net或办公软件中打开/导出并看最终图；检查长文字、公式、裁边、箭头和分组。只检查XML结构不能称视觉验收通过。
3. 按论文实际栏宽看可读性，必要时缩短冗余文案或拆图，不继续缩字。
4. 交付用户要求格式，说明可编辑范围、实际打开/渲染检查状态和仍受环境影响的项目。没有可用渲染器时可以交付XML及静态检查结果，明确视觉检查未完成。
