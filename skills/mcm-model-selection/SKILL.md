# 数学建模模型选择

交付一个有理由、有适用条件、能够验证的选择。先确定要表达的关系，再决定数学形式和计算方法。已有可用模型时，判断是否满足当前任务，不因新调用而全部重选。

## 提取决定选型的信息

读取本题及相关数据说明；项目已有分析或结果报告时只读相关部分，不要求特定文件名。识别：

- 所求的是机理解释、参数估计、未来预测、方案决策，还是评价比较。
- 哪些量已知，哪些是状态、决策或待估参数；它们的单位、定义域及观测方式。
- 硬约束、可接受误差、信息可用时点、计算预算和多问之间的输入输出关系。
- 数据的独立单位：每行是否来自同一个体、设备、时间段或地点；哪些变化能由现有数据识别。

区分题目给定、用户选择和建模假设。缺失条件会改变模型类别时，提出具体问题或给条件分支；可以继续的部分直接完成。不要用默认常数或虚构数据填补关键缺口。

## 形成短名单

按需查看 [结构选型示例](references/structural-routing.md)，只用与当前任务相符的分支。先建立能够覆盖题目要求的简单基线，再看复杂方案是否解决了基线的具体不足。

候选之间应存在实际取舍，例如可解释性与表达能力、离散精度与计算成本、数据需求与可识别性。数据不足时允许结论为“目前不能唯一选择”，并指出最有价值的补充信息。不要为了凑备选列出明显不适用的方法，也不要给主观评分伪造精确权重。

对保留候选说明：

| 项目 | 应交付的信息 |
|---|---|
| 任务对应 | 该模型生成哪个所求量，接收哪些前序结果 |
| 数学定义 | 必要的状态或观测关系，或目标函数、变量和约束 |
| 使用前提 | 数据结构、机制假设、可识别条件与信息时序 |
| 选择理由 | 它利用了本题的什么结构 |
| 局限 | 何种情形会不可行、偏差过大、过拟合或计算超预算 |
| 检查与切换 | 用什么证据保留它；出现什么问题改用备选 |

把模型、求解器和验证工具分别命名。例如整数资源分配属于模型结构，分支定界属于算法；换软件不等于换模型。仿真或采样可用于评估，但还需定义被模拟的状态、决策和机制。

## 将选择落实为可检验方案

选择与核心主张有关的检查，避免没有意义的固定清单：

- 决策模型：将输出代回全部硬约束，并说明最优性证据能覆盖的范围。
- 预测或估计：按实际使用场景划分训练与验证数据，检查辨识性和误差定义。
- 机理模型：核对单位、边界和守恒关系，并针对目标输出评估离散误差。
- 随机或不确定模型：说明随机性来源、信息可用时点与情景依据；估计误差和方案稳定性分别报告。

只依据已执行的检查描述性能。求解器返回成功、拟合曲线接近或一次随机运行，都不能单独支撑超出其范围的结论。涉及陌生方法前提或特定软件行为时，查阅当前权威资料后再作具体承诺。

## 交付

先给推荐方案及主要理由，再提供逐问依赖、保留候选的比较、数学骨架和下一项验证工作。每个优缺点都联系题目，避免“精度高、复杂度低”等无条件评价。

思路请求直接在对话中回答；需要文件时写入项目已有报告或用户指定位置。标明尚未运行的部分。此技能独立可用，不要求安装其他技能；后续求解、创新设计或论文修改只按用户请求展开。
